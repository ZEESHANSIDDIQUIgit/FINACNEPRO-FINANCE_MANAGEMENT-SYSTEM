🔐 Security Note

This app currently trusts the userId stored in your browser's local storage to identify you to the API. That's fine for a personal or demo project, but before showcasing this publicly, move authentication to the backend: login should issue a JWT or HTTP-only session cookie, and every API route should verify that cookie/token server-side rather than trusting an ID sent from the client. This is a backend change — it can't be completed from this HTML file alone.
